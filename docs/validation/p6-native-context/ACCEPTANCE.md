# P6-T04 native Context delivery — bounded acceptance

Scope: a real isolated Codex CLI turn receives the exact Core-built Context; a read-only Dashboard view distinguishes build records from historical native-input matching. Not ordinary Desktop auto-injection, full T04 tool/Evidence/State integration, independent signoff, P4 benefit or whole P6 acceptance.

Use a separate rehearsal database/workspace/ports, leaving the current isolated Dashboard, its trusted Desktop capture definitions, running Hindsight and daily services unchanged. Reuse Host Hook Protocol for Context generation and the native typed-input proof contract. No schema migration or new Truth-writing route.

The collector may publish a private write-once receipt only after matching a completed real native turn, exact same-turn developer input, source native session/turn, emitted bytes, Core pack hash, task/host and current-check receipt. An assistant saying “received” is insufficient. Core reads only an operator-configured private receipt directory, verifies its structure/bindings and exact typed input, and returns a minimal metadata projection. This trusts the local host collector/file owner, not a model-provided Raw Event; it is not tamper-proof storage against that owner. Original native transcripts stay private.

Required negatives: no receipt/configuration; mismatched bytes/pack/source/session/turn; assistant or user quote; wrong turn; malformed/oversized/symlinked/unsafe private file; insufficient API scope; stale historical delivery must never imply current use. Browser reads only, no secret storage or raw transcript exposure. Preserve unsuccessful attempts and compare service/config/PID boundaries before/after.
