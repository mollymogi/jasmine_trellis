# Jasmine Core 0.2.0 单机正式版

本版本发布单机 Core 与 Dashboard，数据库 schema 13。它不是完整 P0–P7/V1 验收签署。现有阶段报告保留原始范围与失败记录；实际部署结果单独记录，不由版本号推定。

## 本次交付

- Memory 概览以一句话说明状态，展开查看运行细节；历史 Memory 可以对照其来源 Rule 的当前版本、变更与退役状态。比较不改变 Authority、State 或 Memory。
- 侧栏、主题与页面层级对齐 mogi-ui；会话按 Core seq 展示用户和助手消息，系统事件默认折叠，显示本地时区，每三秒增量刷新。刷新失败保留已读内容。
- 明确绑定并由用户信任的项目可以采集真实 Codex 会话。采集核对原生持久会话头，不把无来源的后台预测输入当作普通用户发言。
- 显式配置的 CLI Context 接收凭证可以在看板读回。它证明对应历史轮次存在与 Core 完全相同的原生 developer 输入，不证明当前轮次仍使用、后续行为正确或独立验收通过。
- 本机引擎启动是可选运维功能，需要操作者预配置启动配置和专用权限；浏览器不能选择命令或获得模型密钥。已有外部 Hindsight 保持外部服务，不伪装成由 Core 管理。
- Host Hook Protocol 与真实 Gate 决定可在看板读回；schema 12 升级只增加 migration 13，原已发布迁移不改。

## 功能边界

普通聊天不会自动变成硬规则或记忆。对话采集、Interpreter/Resolver、审批、Memory worker 和原生注入各有独立配置与来源条件。新安装默认不会改 Codex 信任、安装全局 Hook、连接 Hindsight 或启动模型调用。

真实桌面采集与 Hindsight 写入的已有证据来自隔离环境；Context 本轮接收证据来自单个真实 CLI 会话。部署 Core 不会把隔离项目自动改绑至日常项目，也不复制隔离 DB、记忆或接收凭证。生产中的实际可用性由生产验收记录说明。

P4 收益实验保持停止；通用桌面自动 Context 注入、多设备心跳/离线同步、完整 Scenario Runner、manual-reapply、完整 P6/P7/V1 验收仍未交付。本次未产生独立人工签署。

## 安装与校验

需要 Python 3.11+、Node.js 20+；本次实际安装验证使用 macOS ARM64、Python 3.13。Core 基础功能无第三方运行依赖；Context 需要 `tiktoken==0.14.0`。Hindsight 另行部署，不包含在包中。

发布附件包含 Python wheel、带已构建 Dashboard 的源码包、逐文件清单和 `SHA256SUMS`；不包含虚拟环境、数据库、密钥、原生转录、机器配置或 node_modules。GitHub 自动生成的源码压缩包不含 `web/dist`；使用发布附件中的 bundle，或者自行运行 `npm ci && npm run build`。

在一个全新目录下载并校验附件后解压 bundle：

```sh
shasum -a 256 -c SHA256SUMS
# 下面命令只用于新的安装目录；已有日常部署按升级节执行。
mkdir -p data
python3 -m venv .venv
.venv/bin/python -m pip install './wheels/jasmine_core-0.2.0-py3-none-any.whl[context]'
.venv/bin/python -m pip check
.venv/bin/python -I -m jasmine_core.cli --version
.venv/bin/python -I -m jasmine_core.cli migrate --db ./data/core.db
.venv/bin/python -I -m jasmine_core.cli serve --db ./data/core.db --host 127.0.0.1 --port 8787
```

首次安装先创建 `data/`。需要浏览器读权限时，使用 CLI `bootstrap --help` 为明确的操作者建立主机、actor 和最小权限 key；终端输出的 key 属于私密凭据，不应提交或贴到公开问题中。另开终端启动 Dashboard：

```sh
P6_CORE_ORIGIN=http://127.0.0.1:8787 P6_ENABLE_P3_READS=1 P6_ENABLE_P7_READS=1 \
node web/server/serve.mjs --root web/dist --host 127.0.0.1 --port 15180
```

Memory 读写仅在明确配置引擎、worker 与权限后启用对应开关。现有日常安装继续使用原有 runtime 配置与 LaunchAgent；不使用这段示例替换它们。

## 从 schema 12 升级与恢复

1. 在独立副本中用同一安装包运行 12→13，检查旧 migration checksum、完整性、外键和原业务行；再验证 12/13 两条恢复路线以及旧程序拒读 13。失败不切换。
2. 暂停 Dashboard、Memory worker、Core 新写入，保持 Hindsight/PostgreSQL 运行。用 SQLite online backup API 保存停写后的最新 12 库，同时备份 runtime、启动器及 plist。目录 0700、凭据文件 0600。不能把此前演练快照当作切换快照。
3. 安装新包到独立 release 目录，运行 migrate，只允许 `m0013_host_hooks`。核对数据后，原子切换 runtime 中 commit/release/python；原端口、工作区、凭据、引擎与其余开关保留。按 Core→worker→Dashboard 启动并在原入口验证。
4. 旧程序不能读 13。若升级后必须恢复 12，先停止三服务并保存完整的最新 13 库及其新写入，再恢复此次停写快照和旧 runtime；这是恢复快照，**不是无损降级**。不得直接调用旧 `rollback-config` 把 schema 13 交给旧代码。
5. SQLite 备份不覆盖 Hindsight PostgreSQL 或 Keychain。引擎没有重启或替换时不声称进行了引擎恢复；重建引擎需要另做投影、游标和远端内容核验。
